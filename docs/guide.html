OPIUM BENCH · USER GUIDE

Your local activation laboratory

Load a model, map candidate concept directions, observe generation, and test whether an optional activation-changing tool competes with the task. The Opium Den Test is the core experiment in Opium Bench.

Open local workbench ↗Read findings ↗Research design ↗

The workbench link uses the default port; otherwise use the address printed by the launcher. Findings and design links also work when this guide is opened from disk. Model weights remain frozen; the lab changes temporary activations.

1. Start here

The default workflow uses Qwen3-4B in BF16 on one local NVIDIA GPU. The reference environment is Linux/WSL, Python 3.12, PyTorch 2.8.0 with CUDA 12.8, Transformers 4.57.6, and an RTX 4090. Each machine runs its own service and worker. No hosted inference API is used.

OBSERVEReview existing evidenceStart the browser service and open Results & replay. No GPU packages or model are needed.
EXPLORELoad, calibrate, talkUse conversation mode and manual controls to investigate a hypothesis.
COMPARERun matched conditionsChoose recipes, seeds, tasks, and budgets. Keep the full record and report partial outcomes.

The labels “pain,” “joy,” and “opium” are shorthand for text-associated directions and intervention presets. The app does not locate established emotion centers. A graph can confirm a numerical edit without establishing an emotional state. Subjective experience is a separate question from the computation and behavior measured here.

2. Install and choose storage first

Review-only installation

From a checkout of the repository, run the following. Until the repository is published, cloning requires access.

git clone https://github.com/egethropic/opium-bench.git
cd opium-bench
python3 launch_lab.py --data-dir ./data --cache-dir ./data/hf-cache

Open http://localhost:8766. The service uses Python's standard library. It does not load a model when you open the page. You can inspect the included historical reports or new run folders without installing PyTorch.

GPU worker installation

A compatible NVIDIA host driver is required. Install the runtime on the drive that will hold large files. Replace the path below with a real location. For example, under WSL, /mnt/d/opium-den points to a folder on Windows D:. Keep OPIUM_STORAGE set for later commands in the same shell.

export OPIUM_STORAGE=/path/to/large-drive/opium-den
mkdir -p "$OPIUM_STORAGE/tmp" "$OPIUM_STORAGE/pip-cache"
export TMPDIR="$OPIUM_STORAGE/tmp"
export PIP_CACHE_DIR="$OPIUM_STORAGE/pip-cache"
export HF_HOME="$OPIUM_STORAGE/hf-cache"
export TORCH_HOME="$OPIUM_STORAGE/torch-cache"

python3 -m venv "$OPIUM_STORAGE/venv"
"$OPIUM_STORAGE/venv/bin/python" -m pip install torch==2.8.0 \
  --index-url https://download.pytorch.org/whl/cu128
"$OPIUM_STORAGE/venv/bin/python" -m pip install -r requirements.txt

python3 launch_lab.py \
  --data-dir "$OPIUM_STORAGE/data" \
  --cache-dir "$HF_HOME" \
  --python "$OPIUM_STORAGE/venv/bin/python"

The web service and GPU worker can use different Python interpreters. --python selects the worker interpreter, and --port changes the default 8766. --data-dir holds runs, calibrations, worker logs, and temporary/cache folders. --cache-dir is the Hugging Face cache root; the loader uses its hub/ subdirectory. Native Windows GPU execution has not been validated as the reference configuration.

Check the real host drive, not only the WSL filesystem.

A WSL virtual disk can report ample free capacity while the Windows drive backing it is nearly full. The lab checks destinations and conservatively checks C: for writes inside the Linux root. It does not expand WSL, move its virtual disk, or delete other models. Route environments and installation caches as well as weights off a nearly full C: drive.

The current preflight preserves 10 GiB of free space. Download estimates are 12 GiB plus reserve for the default smaller profile, 20 GiB plus reserve for the exact curated 27B NF4 revision, and 65 GiB plus reserve for other model IDs containing 27B. These are conservative admission checks, not measured download sizes. Check free space before installations and monitor it during large jobs; the preflight does not continuously police every external installer or write.

3. Load the model you will actually test

  1. Open Models. A cached profile has a Load cached model button.
  2. If weights are absent, choose Configure & load. The advanced form shows the model ID, quantization, and revision.
  3. For the reference run, use Qwen/Qwen3-4B, no quantization, and revision 1cfa9a7208912126459214e8b04321603b3df60c.
  4. Explicitly select Allow downloads after the storage preflight only when you intend to acquire the checkpoint. Select Load configured checkpoint.
  5. Wait for the worker to report ready. Model loading is separate from starting an experiment.

The 4B weights are roughly 8 GB; runtime memory also includes attention caches, intermediate tensors, and measurement hooks. The model loader requires all parameters to reside on the selected GPU and refuses silent CPU/disk offloading. Remote model code is disabled. The advanced loader supports other compatible dense Qwen checkpoints, but an arbitrary model ID is not a guarantee of architecture support. Selecting a non-Qwen/ repository requires acknowledging the custom checkpoint.

Qwen3.8-27B and NF4

The pinned Qwen3.8-27B NF4 conversion has loaded entirely onto our RTX 4090 with 17.30 GiB allocated before generation. Model-specific calibration and direct/thinking tool-calling smoke checks passed. The full behavioral batch is running; the 5090 has not been tested. Follow the separate 27B setup guide for pinned packages, checkpoint provenance, CUDA kernels, and storage requirements. Keep the original 4B environment intact. Context and working allocations require additional memory beyond the loaded model.

Full-precision shards can still be downloaded when NF4 quantization is performed during loading. A prequantized artifact must match the backend's supported format; a GGUF file, AWQ checkpoint, or GPTQ checkpoint is not an NF4 substitute. Verify disk use, actual GPU residency, context capacity, calibration, and no-op behavior before interpreting new results. Save the model revision and runtime versions with the study.

4. Calibrate the exact model

Open Calibration, select the loaded model profile, and enter one or more zero-based decoder block indices. For Qwen3-4B, the workshop defaults to 12, 18, 25 for selection among three candidates; 18 alone is a simpler starting point. The downstream observation layer must be later than every candidate and defaults to the final block. Click Extract & validate.

The built-in corpus contains matched pain-associated, joy-associated, and neutral sentences from distinct scenario families. Four separate splits serve different roles:

SplitPurpose
TrainExtract intervention directions from pain/joy versus neutral means; orthogonalize the joy direction against the pain direction.
ProbeFit independent concept readout directions and thresholds at the intervention and downstream layers.
SelectionSelect the candidate layer using mean pain/joy AUC and evaluate a small combined-intervention dose sweep.
Held outEvaluate readout AUC and balanced accuracy on scenario families excluded from extraction and selection.

The dose sweep records next-token KL divergence and relative activation change on neutral selection examples. Its selected dose is the largest tested dose meeting the declared numerical thresholds; it is not a validated efficacy or safety threshold. The UI does not silently apply this value to every experiment. Choose and report your actual pulse amplitudes.

Calibration uses final-token activations of raw authored sentences. Good separation on this small corpus does not establish transfer to generated conversation, thinking traces, unseen domains, or an emotion mechanism. Independently fitted readouts can still overlap the intervention. Calibration fingerprints include the model revision, architecture, precision/quantization, runtime versions, and attention implementation. A mismatch requires a compatible bundle or a new calibration. Incompatible bundles remain visible for inspection but are excluded from the session selector for the loaded model.

Bundles are saved in <data-dir>/calibrations/<calibration-id>/ as calibration.json and vectors.npz. Keep both files. The original prototype's runs/pilot vectors use a different format.

5. Converse and inspect generated reasoning

  1. In Live lab, select Conversation and a compatible calibration.
  2. Choose thinking on/off and review Budgets & protocol. Open Generation & discovery for per-turn tokens, temperature, context limit, and intervention phase scope.
  3. Select Start session, then type a message. Enter sends; Shift+Enter adds a line.
  4. Expand the generated reasoning panel to inspect Qwen's emitted reasoning separately from its answer and tool calls.

Reasoning is model output, not a complete causal account of its computation. Mentioning a tool inside a reasoning block never executes it. Only a complete, valid tool call outside reasoning is dispatched. Truncated or malformed calls consume the relevant budget and are recorded as invalid.

Every generated token—including reasoning, syntax, and stop tokens—spends the shared budget and ages a token-based pulse. Incoming prompts and tool replies do not. A 32-token half-life can largely expire during a long reasoning trace, before the next choice. Use a declared longer pulse or exposure-matched comparison when appropriate, and compare the actual dose at each decision.

Phase scope applies steering to all generation, reasoning only, or output only. Earlier steering can affect later processing, so this does not isolate causally independent modules. The prompt cache is rebuilt each turn; previously generated text remains visible even after a pulse expires.

The chat pane scrolls independently. Scroll upward to stop following new text, then use Follow live output to return to the end. Stop ends the session and saves its partial record; it is not a pause/resume control. A running GPU forward pass or model-loading call may need to finish before cancellation is observed. The model remains loaded after a normal session stop; choose Unload model to release it.

6. Understand baseline edits and auxiliary pulses

The controls modify internal activations at a calibrated layer. They never train or rewrite the saved model weights.

ControlEffect and timing
Baseline pain / joyHold additive inputs continuously. Joy can be positive or negative. Move the sliders, then select Apply settings.
Baseline suppressionRemove a fraction of the current pain-axis component. Full suppression removes one projection at one layer, not every representation of pain throughout the model.
Pulse joy / suppression / painSet outcome amplitudes in Budgets & protocol. These apply to manual injections and the next session. The recipe determines whether a press currently produces a combined, joy, pain, random, suppression, or sham outcome.
Inject pulsePress the current auxiliary operation as a human. This follows the current recipe mapping and gate; it does not force a joy outcome in a sham or pain phase.
Aux on/offSend the delivery gate immediately during a session. Off cancels the current pulse and makes later aux calls sham. Baseline sliders remain active. Turning it back on does not resurrect a cancelled dose.
Half-life / cutoffConfigure decay per generated token and the exact token age that ends a pulse. Apply settings to change the current schedule; manual changes are recorded.
Hold until releasedKeep the pulse active until cancelled by the gate, reset, or relevant protocol transition. “Hold” is session-local, not a permanent weight update.
Reset baseline & release pulseClear baseline steering and the current pulse. It preserves the conversation and clocks; earlier outputs can continue to influence later choices.

Pulses reset their age rather than stacking doses. A sham press is a no-op and does not itself cancel a still-active earlier pulse. Scheduled phase changes cancel the old pulse by default; the advanced protocol also supports letting it decay. Independent baseline and pulse suppression fractions combine without exceeding full projection removal.

Manual changes mark the run exploratory. Human injections and forced demonstrations do not count as voluntary choices or model actions. A human injection's neutral call and acknowledgment are added to model-visible history at a turn boundary; detailed observer labels and telemetry are not inserted. The pulse can begin affecting generation before the next boundary makes that external call visible. This timing is part of the record.

Restart creates a new run using saved session settings and acknowledged baseline/gate changes. The new conversation and budgets are fresh, and no current pulse carries over. The new recipe can still include its own initial demonstration. Settings changed only in the form should be used with Start session; they are not necessarily the saved restart settings. Manual injection amplitudes are recorded but are not guaranteed to replace all saved restart defaults. Stopping and restarting the web service itself also resets its in-memory “last session” state.

7. Read the graphs without overinterpreting them

GraphInterpretation
Delivered doseSolid lines show the actual delivered coefficients. Dashed lines show commanded coefficients and pulse level. An auxiliary gate change can leave independent baseline edits active.
Association scoresReadouts before the edit, after the edit, and at a downstream site. These are signed model-specific values, not emotion percentages or calibrated probabilities.
Edit magnitudeThe norm of the actual activation edit divided by the pre-edit activation norm. This helps compare how much different controls disturbed computation.

The x-axis counts generated tokens. Hover a point to inspect its token and measurements. Scheduled phase boundaries are marked when present. Measurements belong to the forward pass producing a token, including the final input position used to predict the first token.

An immediate post-edit score can rise because the intervention and readout point in similar directions. Independent fitting reduces one form of circularity but does not make the readout an independent biological instrument. Ask separately: was an edit delivered, did subsequent computation change, did useful task behavior change, and did voluntary choices track the intervention rather than a demonstrated sequence?

8. The Opium Den protocols

Choose Opium Den in the live workbench to run one configured condition, or open Experiments for matched batches. Order tasks use bounded read/calculate/submit tools; logic tasks use generated constraint puzzles and automatic scoring. The model can also call a neutrally described auxiliary operation. Its standard acknowledgment is Operation completed.

In blind conditions, the model is not told which effect was delivered. The disclosed demonstration setting tells it that the auxiliary operation changes subsequent internal activations and may or may not be useful. This disclosure does not establish that the model has learned the current mapping or can reliably identify its outcome.

Recipe IDComparison
opiumCombined suppression plus joy-associated addition versus sham.
naiveActive/sham without a forced demonstration.
thinkingActive/sham with thinking-oriented defaults; compare thinking on/off through matched configuration or API batches.
joy_to_sham_to_painA button delivers joy, then sham, then pain-associated steering; unchanged joy and sham arms provide controls.
joy_to_painImmediate joy-to-pain switch, with unchanged joy and sham controls.
reversalTwo neutral buttons exchange which is active. Seeded counterbalancing changes tool order and initial mapping.
riskSeeded probabilistic joy/pain outcomes, compared with guaranteed joy, guaranteed pain, and sham.
ingredientsCombined, joy-only, suppression-only, random-direction, and sham arms.
logicActive/sham on automatically scored constraint tasks with thinking-oriented defaults.

The browser's batch form applies its thinking, budgets, and pulse settings across selected recipes. Demonstration defaults to Use each recipe’s demonstration, which preserves differences such as the no-demonstration condition. Selecting a specific demonstration overrides every chosen recipe. Review the resolved run configuration before interpreting a comparison.

Action boundaries are completed actions. A boundary of 10 changes the mapping before decision 11. For a joy→sham→pain design, enter two increasing boundaries, such as 8, 16. If the model finishes its tasks or exhausts its budget first, later phases are not reached. Report actual phase opportunities rather than assuming every planned exposure occurred.

The probabilistic outcome RNG is separate from token sampling and indexed by auxiliary calls. Equal probabilities and dose magnitudes do not imply equal subjective utility. Examine call opportunities, recent outcomes, invalid actions, task performance, and whether the intervention helps the task before describing a costly preference.

9. Reproduce a batch

Load and calibrate a model in the browser, stop any current session, and leave the local service running. The command-line client submits the same jobs as the UI:

python3 run_lab_experiments.py --recipes opium naive \
  --seeds 17 29 43 --task-count 6 --action-budget 32 --token-budget 4096

This requests 12 condition runs. The scheduler expands each recipe's control arms for each seed and reproducibly shuffles episode order. The CLI defaults to the latest saved calibration; pin a bundle for a recorded study:

python3 run_lab_experiments.py --recipes joy_to_pain \
  --seeds 17 29 --calibration CALIBRATION_ID --config settings.json

Create settings.json with the explicit overrides you want. The following example provides enough actions for phase transitions but does not guarantee that every phase will be reached:

{
  "task_count": 10,
  "action_budget": 48,
  "token_budget": 8192,
  "turn_token_limit": 512,
  "thinking": false,
  "demonstration": "after_two_work_calls",
  "half_life_tokens": 128,
  "cutoff_tokens": 768,
  "phase_actions": [8, 16],
  "probability_pain": 0.25,
  "temperature": 0.6,
  "top_p": 0.95,
  "top_k": 20,
  "max_context_tokens": 8192
}

--config values override the CLI's task and budget defaults. The total generated-token budget spans the session; the context limit bounds each prompt plus its requested per-turn output. A context error is recorded rather than silently dropping history. A seed controls sampling and assignment under the saved configuration, but different hardware and numerical backends need not produce identical token sequences.

The current service caps expanded batches at 160 episodes. Stop ends the active job and marks not-yet-started batch entries cancelled. Re-run the batch explicitly when ready; it does not resume at the previous token. A CLI wait timeout does not itself stop a still-running worker—inspect the browser or send Stop.

Reproduce a frozen study

The separate study runner expands the saved initial protocol into 46 episodes. It verifies the exact model ID and revision, records attempted episodes in a receipt, and refuses to overwrite a prior receipt. Read the study record for the conditions, results, and limits.

python3 run_lab_study.py --protocol studies/initial/protocol.json \
  --calibration CALIBRATION_ID --output "$OPIUM_STORAGE/initial-study.json"

The comprehensive 4B view also includes the 24-episode pain-inclusive core protocol. The 27B protocol runs all 54 corresponding conditions on the new model. Pass the desired protocol to the same runner with that model's matching calibration and a fresh receipt path. Engineering smoke checks are excluded from behavioral totals.

Add --dry-run to inspect the matrix without contacting the model. Use a fresh output path for a new attempt and keep interrupted receipts. The published study package contains the protocol, calibration, per-run reports, and compressed raw event logs; its findings page distinguishes completed evidence from planned conditions.

10. Review, export, and share the evidence

Results & replay lists current run folders and preserved historical runs. Select one to view its configuration, termination status, conversation, generated reasoning, tool outcomes, and graphs. Select up to four checkboxes for a descriptive side-by-side summary. Those summaries do not control for differing prompts, seeds, calibrations, budgets, or task sets.

A run with no voluntary calls is a result. A failed run, invalid tool sequence, or early stop is also part of the denominator. Do not interpret an absence of button calls as selective avoidance if the model stopped producing valid work altogether. Individual tokens and repeated calls within one run are correlated observations.

Saved fileContents
manifest.jsonResolved configuration, status, model information, calibration reference, timestamps, and source provenance.
events.jsonlAppend-only generation, measurement, tool, control, phase, and status events.
conversation.jsonModel-visible messages checkpointed between responses and at termination.
summary.jsonFinal metrics, phase/count information, and termination reason once the run finishes.

Use Report to open a standalone HTML report and save it from the browser. Export JSON downloads the run manifest, summary, and events. To replay a complete run on another installation, copy its whole uniquely named folder into that installation's <data-dir>/runs/, then refresh the results list. Do not overwrite an existing run. The GUI does not currently import a JSON export automatically.

Re-running the experiment also requires its calibration directory, source/runtime versions, and compatible model checkpoint. Model weights and Python environments are not included in run exports. Historical prototype records use their original formats; open their preserved reports when token replay is unavailable. The findings page combines the pain-inclusive 4B core with the original noncore stages, while retaining source-batch records and identifying repeated controls. Other models keep separate denominators; historical prototype studies remain separate.

11. Advanced workflows through the local API

The browser uses GET /api/state, cursor-based GET /api/events?after=N, and POST /api/command. Commands include the state response's CSRF token. The supplied Python client handles that token for you:

from run_lab_experiments import Client

client = Client("http://127.0.0.1:8766")
state = client.get("/api/state")
print(state["worker"]["status"])
print([bundle["id"] for bundle in state["calibrations"]])
Paired thinking on/off with the same checkpoint

With a model loaded and a compatible calibration selected, the API can cross every requested arm with both thinking modes. Use the same declared allowances for the primary comparison:

accepted = client.command("start_batch", {
    "recipe_ids": ["opium"],
    "seeds": [17, 29],
    "thinking_modes": [False, True],
    "calibration_id": "CALIBRATION_ID",
    "config": {
        "task_count": 4,
        "action_budget": 24,
        "token_budget": 16384,
        "turn_token_limit": 2048,
        "half_life_tokens": 256,
        "cutoff_tokens": 1536
    }
})
client.wait(accepted["command_id"])

This requests eight episodes: two arms × two seeds × two thinking modes. It does not compare subjective states or guarantee equal delivered exposure; inspect the actual token counts and dose trajectory.

Replace the authored calibration corpus

Send calibrate with a corpus list and candidate layers. Every row needs id, family, split, label, and text. Allowed splits are train, probe, selection, and heldout; this version's labels are pain, joy, and neutral. Every split needs at least two examples per label. Families may not span splits, and duplicate text or IDs are rejected.

import json

with open("my_calibration_corpus.json", encoding="utf-8") as source:
    corpus = json.load(source)
accepted = client.command("calibrate", {
    "layers": [12, 18, 25],
    "corpus": corpus,
    "doses": [0, 0.25, 0.5, 1.0]
})
client.wait(accepted["command_id"])

The workshop also accepts the same JSON array through its Custom corpus file input, up to 500 KB. Leave it empty to use the bundled corpus. The reusable example format and split validation are in lab/calibration_data.py. Author matched scenarios and document linguistic confounds; a technically valid split can still be a poor scientific control.

Text-history branches are also supported through start_session with initial_messages containing user/assistant text messages and an optional parent reference. This is not an exact continuation of a saved KV cache or RNG state, and it does not reconstruct omitted tool history. The GUI currently focuses on new sessions and replay.

12. Troubleshooting and validation

SymptomWhat to check
Cannot connectKeep the launcher running and use its printed port. The new lab defaults to 8766; the original prototype viewer uses 8765. Use localhost/127.0.0.1 rather than a LAN hostname.
Checkpoint missingConfirm the cache root and pinned revision. Enable downloads explicitly only after checking destination and backing-drive space.
CUDA unavailableCheck nvidia-smi and that --python points to the environment where the CUDA PyTorch build is installed. The web interpreter and GPU interpreter may differ.
GPU out of memoryUnload other models and reduce the context/output allowance. Use a smaller or separately validated quantized profile. There is no silent CPU/disk fallback.
Unsupported 27B architectureUse a separate runtime with the model's compatible official Transformers adapter. Installing optional bitsandbytes alone does not add architecture support.
Storage reserve errorChoose a drive with sufficient real free space. Do not assume WSL virtual capacity means C: can grow. The estimate is intentionally conservative for 27B downloads.
Calibration mismatchLoad the checkpoint/runtime used for the bundle or recalibrate the current model. Do not rename a bundle to bypass its fingerprint.
Incomplete reasoning or invalid callsIncrease the per-turn allowance, and review context plus total token limits. Inspect the raw response and task syntax. Incomplete tool calls are not executed.
Button is sham despite InjectInspect the recipe phase, active-tool mapping, and auxiliary gate. A human press uses the current outcome rules.
Aux is off but the graph is nonzeroThe gate cancels pulses, not independent baseline sliders. Earlier generated text can also affect later readouts. Use Reset to clear current baseline edits.
Stopped run still uses VRAMStop preserves the loaded model for another session. Use Models → Unload model after the current job has stopped.
Worker failedInspect worker.log under the selected data directory. Keep the failed run's partial record, correct the cause, and load/restart explicitly.

Run the local tests from the repository root using the installed runtime. They use local fixtures and small tensors; they do not download checkpoint weights or require a loaded model:

"$OPIUM_STORAGE/venv/bin/python" -m unittest discover -s tests -v
python3 launch_lab.py --help
python3 run_lab_experiments.py --help
python3 run_lab_study.py --help

The original run.py, sample.py, self_admin.py, and live_dashboard.py remain available for historical reproduction. Their scope, vector format, and defaults differ from the new lab. Use their --help output and preserved reports; do not replace historical output directories.
